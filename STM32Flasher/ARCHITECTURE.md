# STM32 烧录器架构

## 目标

这是一个面向 STM32F103C8T6 与 ST-Link 的原生 macOS 工具。它负责四件事：

1. 编辑 C 源码。
2. 用 ARM GCC 构建固件。
3. 用 STM32CubeProgrammer CLI 检测和烧录目标芯片。
4. 把设备、编译、烧录结果以有界日志显示给用户。

应用不联网，不上传源码，也不自动安装工具链。

## 模块边界

| 文件 | 职责 | 不应该承担的职责 |
| --- | --- | --- |
| `STM32FlasherApp.swift` | App 入口、页面组合、动作路由 | 启动子进程、解析编译结果 |
| `CodexComponents.swift` | 颜色、按钮、面板等复用视图 | 持有设备或工程状态 |
| `WorkspaceScanner.swift` | 后台有界扫描、完整目录树和编译范围判定 | UI、保存或进程执行 |
| `WorkspaceFileOperations.swift` | 工程内创建、重命名、名称及路径安全校验 | UI、编译或设备操作 |
| `BuildProcessSupport.swift` | 子进程取消、超时、输出硬上限与烧录结果纯校验 | UI 或设备状态 |
| `ExplorerInlineEditing.swift` | 资源树的新建、重命名输入控件和请求类型 | 磁盘读写或工程状态 |
| `ExplorerComponents.swift` | 缓存后的文件夹树、根文件夹和文件行视图 | 读取或保存源码 |
| `MoveDestinationSheet.swift` | 只展示工程内文件夹的移动目标选择器 | 执行文件移动 |
| `FlasherModel.swift` | 状态、打开的编辑器、工程文件、编译、烧录、进程生命周期 | 大段内置模板、通用 UI 样式 |
| `ToolchainResolver.swift` | 查找本机 CLI 与 ARM GCC | 下载、安装、联网 |
| `SyntaxHighlightedCodeEditor.swift` | 文本编辑、高亮、撤销和大小保护 | 编译、烧录 |

## 主要数据流

```text
用户操作
  -> 固定侧栏与烧录/代码页
  -> FlasherModel 校验输入与资源上限
  -> ARM GCC 或 STM32_Programmer_CLI 子进程
  -> 有界输出捕获
  -> operation ID 检查
  -> 主线程更新结果、进度和日志
```

取消设备操作时会立即清除当前 operation ID；取消编译时会使当前 build ID
失效。进程控制器把“登记、启动、取消”线性化，启动前已经收到取消的进程不会
再被启动。所有编译、探测、连接、复位和烧录命令都有明确超时；超时或取消时
先终止进程，宽限期后仍未退出则强制结束，同时关闭读取端，防止派生进程占用
输出管道拖住任务。旧回调不得覆盖新的 UI 状态。

文件界面使用“当前编辑缓冲区 + 有界打开文件列表 + 完整工作区条目 +
可编译工程文件列表”四层状态。
新建缓冲区不得清空工程或打开文件；切换文件必须先由 UI 处理未保存修改。
打开磁盘源码时记录文件版本；保存前若修改时间、大小或文件标识已变化，必须
停止静默覆盖，并由用户选择另存为或明确覆盖。
打开文件列表最多保留 32 项，重启时只恢复最后一个文件或工程，不缓存整份
源码到偏好设置中。打开编辑器按首次打开顺序保持稳定，点击文件不得进行
MRU 重排；后台扫描对所有文件和文件夹合计执行 2,000 项硬上限，刷新不得
切换当前文件，目录树只在扫描结果变化时重建。扫描错误只保留有限条目用于
诊断；发现读取失败时不得把不完整的目录树当成一次成功刷新。

目录树使用纯展示层的递归节点：任意深度的子文件夹、空文件夹和非代码文件都
保留在同一棵树中。左侧只保存展开、选择和临时名称输入状态；实际创建、移动
与重命名必须回到模型并经过工程路径边界、符号链接和同名覆盖检查。新建文件
使用排他创建，已有文件绝不截断。“全部展开”和“全部收起”不会触发新的磁盘
扫描，也不会改变当前编辑器或编译范围。
打开新工程的异步扫描期间，编辑器进入只读状态；扫描开始时记录源码编辑代数，
若仍发生新的输入，扫描结果不得替换当前缓冲区。

编译范围由当前编辑器决定。选中工程内文件时构建工程；工程外文件和未命名
缓冲区使用单文件构建。任何自动保存失败都必须中止编译。构建回调携带 build
ID，代码修改或取消后，旧构建不得写回固件状态。

## 资源安全线

以下限制是产品安全要求，不是临时调试参数：

| 对象 | 上限 |
| --- | ---: |
| 单个源码文件 | 1,000,000 bytes |
| 固件文件 | 16 MiB |
| 单次编译 C 文件数 | 128 |
| 工程枚举文件数 | 2,000 |
| 单个命令捕获输出 | 1 MiB |
| 单次构建汇总输出 | 512,000 characters |
| UI 日志 | 200,000 characters |
| 可编辑文本 | 1,000,000 characters |
| 执行语法高亮的文本 | 250,000 characters |
| 单次语法高亮匹配 | 100,000 spans |
| 撤销层数 | 30 |

修改编辑器、日志、工程扫描或子进程代码时，必须证明这些边界仍然有效。
构建和测试的 Swift 模块缓存位于系统临时目录，工程 `build` 目录只保留最终
签名后的 App，避免可再生产物长期占用磁盘。

## 硬件约定

目标芯片是 STM32F103C8T6：Cortex-M3、64 KiB Flash、20 KiB RAM。检测必须
同时确认 ST-Link 探针和中密度 STM32F103 目标（Device ID `0x410`），仅发现
USB 探针不得解锁烧录；正式擦除前必须再次确认该 Device ID，降低检测后更换
目标板造成误擦除的风险。

BIN 的完整写入区间必须落在 `0x08000000..<0x08010000` 内，并防止地址加法
溢出。CLI 退出码为零仍不足以报告成功：输出还必须同时包含明确的下载成功和
校验成功证据，且不能包含失败证据。

5631BS 为三位共阳极数码管。面向正面观察：

```text
上排: 12 DIG1 | 11 A | 10 F | 9 DIG2 | 8 DIG3 | 7 B
下排:  1 E    |  2 D |  3 DP| 4 C    | 5 G
```

第 6 脚不存在。用户现有接线为：

```text
1...5  -> PB3...PB7
7...12 -> PA0...PA5
```

PB3、PB4 上电后属于 JTAG。使用这两个 GPIO 的模板必须开启 AFIO，并将
`SWJ_CFG` 设为 `0b010`：关闭 JTAG、保留 SWD。共阳极的段线低电平点亮，
位选高电平使能，每一段必须串联限流电阻。

## 变更与验证

- 日常验证：`./Scripts/check.sh`
- 固件模板变更：ARM GCC 编译通过，0 errors；检查 Flash/RAM 是否越界。
- 进程和日志变更：验证启动前取消、运行中取消、超时、旧回调和输出上限。
- 编辑器变更：验证大文件不会触发无限高亮，切换文件会隔离撤销历史。
- 硬件变更：先检测 ST-Link；只有用户在当前任务明确授权时才能烧录。

发布 UI 或行为变更时，同时更新 `Resources/Info.plist` 的版本号与构建号。
