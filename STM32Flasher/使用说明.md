# STM32 烧录器使用说明

适用目标：STM32F103C8T6
烧录器：ST-Link V2 / V2-1 / V3
系统：Apple Silicon Mac，macOS 13 或更高版本

## 最短使用流程

1. 打开“STM32 烧录器”。
2. 点击“选择文件”，选择 `.hex`、`.bin` 或 `.elf`。
3. 点击“检测设备”，软件会先识别 ST-Link，再确认连接的是 STM32F103 中密度目标。
4. 设备识别成功后点击“开始烧录”。
5. 等待界面明确显示写入和校验都成功；缺少任一项都不会被当作烧录成功。

软件默认执行全片擦除、写入、校验和复位。通常不需要修改任何设置。
点击烧录后，软件会在真正擦除前再次核对目标芯片；复核失败时不会执行擦除。

## 从代码编译和烧录

打开工程后，点击资源管理器顶部的“新建文件”或按 `⌘N`，会在当前选中的
文件夹中显示名称输入框；按回车后才在磁盘上创建真正的空白 C 文件。右键
文件夹还可以新建头文件或子文件夹。未打开工程时，`⌘N` 创建未保存的空白
编辑器。

左侧“资源管理器”只显示工程文件夹的真实目录层级，包括文件、子文件夹和
空文件夹；已打开文件只在编辑器顶部标签中显示，不会复制到左侧顶部。C、H 文件可以编辑；
其他文件会显示，但当前版本不会用代码编辑器打开。单击文件会打开，单击文件夹
名称会把它设为新建项目的目标位置，左侧箭头只负责展开或收起。双击文件或
文件夹名称可以就地重命名：回车或点击别处确认，`Esc` 取消。重命名和移动
都不会覆盖同名项目；当前源码有未保存修改时，修改会跟随新路径保留。

文件和文件夹的常用操作收进右键菜单。文件支持打开、打开方式、另存为、重命名、移动到、
在访达中显示和复制相对路径；文件夹支持新建 C/H 文件、新建子文件夹、
重命名、在访达中显示和复制相对路径。根目录右键还可以展开全部、收起全部
或关闭文件夹。打开空文件夹也被允许，可以随后直接新建第一个源码。

尚未打开工程时，“文件夹＋”仍可点击：选择保存位置和名称后，会创建新的工程文件夹
以及空的 `main.c`，随后自动在资源管理器中打开。
工程树中的文件可以直接拖到工程根目录或任意子文件夹，软件会在磁盘上真实移动并
自动刷新。拖到已有同名文件的位置时不会覆盖；当前版本不会通过拖拽导入外部文件或文件夹。

编译目标以当前编辑器为准：当前文件属于已打开工程时，编译工程中的 C 文件；
当前文件在工程外或是未命名文件时，只编译当前编辑器内容。保存失败时编译会
立即停止，避免使用磁盘上的旧代码。
软件不会因为新建、重命名或移动而删除原有内容；软件重启后会恢复上次打开的
文件或工程文件夹。同名文件只在“打开的编辑器”中增加最短相对路径标识，避免
把不同目录中的 `main.c` 认错。

打开或编辑 C 程序后，先点击“编译”。编译成功后“烧录”按钮才会变为
可用；确认编译输出与 Flash/RAM 占用正常、并点击“检测”识别 ST-Link 和
STM32F103 中密度目标后，再点击“烧录”。

只要代码发生任何修改，之前生成的固件会立即失效，“烧录”按钮也会重新
禁用，必须再次编译。退出软件或打开其他文件前，未保存的代码会得到保存
提示。如果同一个源码已经被访达、其他编辑器或 AI 在磁盘上修改，保存前会
停止直接覆盖，并让你选择“另存为”或明确确认覆盖。

此功能需要本机同时存在 `arm-none-eabi-gcc` 和 STM32CubeProgrammer。

## 常见问题

- 未找到烧录引擎：先安装 ST 官方 STM32CubeProgrammer，或在提示中选择已安装的 CLI。
- 设备未识别：重新插拔 ST-Link，确认 USB 线支持数据传输，然后再次检测。
- BIN 文件：默认写入地址为 `0x08000000`；完整文件必须落在芯片的 64 KiB Flash 内。
- 烧录失败：复制“结果”中的完整日志用于排查。

应用会拒绝过大的源码、固件和命令输出，防止再次出现异常内存占用。
文件夹扫描在后台执行，最多检查和显示 2,000 个文件及目录。
编译、设备检测和烧录命令均有超时保护；取消后不会继续启动尚未运行的命令。
